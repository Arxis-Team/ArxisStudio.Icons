# ArxisStudio.Icons

Набор иконок **ArxisStudio**: контурные пути в клетке 16×16 и контрол `AxIcon`,
который их рисует.

Набор нарисован в одной системе координат. Глиф занимает в клетке ровно
столько, сколько задумано, и стоит там, где поставлен: плюс — 9×9 в середине,
шеврон — 7.6×3.8 ниже центра. Это осмысленная разница, а не небрежность, и
подгонять пути под рамку нельзя — от этого набор рассыпается на глифы разного
размера.

## Подключение

```xml
<Project>
    <ItemGroup>
        <PackageReference Include="ArxisStudio.Icons"/>
    </ItemGroup>
</Project>
```

В разметке:

```xml
xmlns:axi="using:ArxisStudio.Icons"

<axi:AxIcon Data="{x:Static axi:AxIcons.Folder}" Width="16" Height="16"/>
```

В коде:

```csharp
new AxIcon { Data = AxIcons.Folder }
```

Свой путь принимается тем же свойством — `Data="M3.5 8H12.5"`, — если он
нарисован в той же клетке 16×16 и одной обводкой.

## Сетка

Набор нарисован под пиксель, а не «примерно в клетке». Правило одно и разное
для двух способов красить:

* **контур** центрирован на пути, поэтому прямой осевой штрих стоит на
  полупикселе — тогда обводка 1.2 занимает пиксель целиком;
* **силуэт** кончается на самом пути, поэтому его края стоят на целой
  координате — иначе по контуру идёт полупрозрачный ореол.

Дуги и диагонали под правило не попадают: их пиксельная сетка не спасает, а
сдвиг сломал бы касание и наклон. Точка, которой прямой штрих входит в дугу,
из правила выведена по той же причине.

Правило проверяется тестом, а не вниманием автора, и ставится на место
инструментом:

```bash
python tools/normalize.py            # посмотреть, что съехало
python tools/normalize.py --write    # поставить на место
python tools/build.py                # пересобрать AxIcons.cs из файлов
```

## Витрина

```bash
dotnet run --project samples/Icons.Gallery
```

Слева весь набор, справа выбранная иконка: размеры 12–64, увеличение до
пикселей с сеткой по их границам и числа — сколько пикселей закрашено целиком,
а сколько задето еле-еле. Внизу двадцать худших по размазне.

Без окна:

```bash
dotnet run --project samples/Icons.Gallery -- --report
dotnet run --project samples/Icons.Gallery -- --dump Plus
```

Первое печатает меру по всему набору — им сравнивают до и после правки.
Второе рисует одну иконку клетками: видно не только что она мутная, но и
почему.

В Debug витрина поднимает [AvaDevTools](https://pavel-zheltiakov.github.io/AvaDevTools/)
на порту 5173 — дерево, стили и снимок любого элемента.

## Контрол lookless

`AxIcon` — `TemplatedControl`, и собственного вида у него нет: цвет, толщину
обводки и заливку задаёт тема (`ArxisStudio.Themes.Arxis`). Без темы контрол
поднимется, но не нарисуется — ровно как контролы `ArxisStudio.Controls`.

Поэтому здесь и не лежит проверка отрисовки: рисовать нечем. Здесь проверяется
сам путь — что он совпадает с файлом, стоит на сетке и не уехал от
дизайн-проекта дальше полупикселя, — а отрисовка проверяется в репозитории
темы, где есть чем рисовать.

## Почему отдельно от контролов

Ни один контрол `ArxisStudio.Controls` набор не зовёт: иконки в шаблоны ставит
тема, а в интерфейс — само приложение. Библиотека контролов и набор глифов —
две разные вещи, которые растут порознь и порознь же переиспользуются.

## Сборка

```bash
dotnet build ArxisStudio.Icons.slnx
dotnet test tests/ArxisStudio.Icons.Tests
```

Репозиторий самодостаточен: соседей рядом не ждёт, зависит только от Avalonia.
